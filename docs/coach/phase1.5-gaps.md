# Phase 1.5 — 未対応・制約・リスク

## 1. 判断の記録（運用方針への追加）

Phase 1 で決めた「Undo を有効にしてプレイする」運用は維持する。Phase 1.5 で追加したのは、履歴とゲームが食い違ったときに**過去の判断を信用しないための安全策**（`rollback-detected` / `uncertain` の判定と `series` 表示）であり、Undo 無効ゲームの復旧機能ではない。自動復元・セーブ方式の変更・ゲームの巻き戻し操作は行わない。

注意: タブレットは作成画面の前回設定を復元するため、2026-10-14 07:54 にタブレットで作成されたゲームは **Undo 無効**だった。次回作成時に一度 Undo を有効にする必要がある（以降は保存される）。

## 2. 未対応・制約

| ID | 内容 | 影響 | 今後 |
|---|---|---|---|
| P15-1 | 実際に別 UID が所有するファイルでの拒否試験 | root 権限が必要。UID 判定の差し替えで試験済み、別 UID からの読取拒否は実機確認済み | 必要なら sudo 可能な環境で追加 |
| P15-2 | フォルダの途中経路（親ディレクトリ）がリンクの場合 | 最終フォルダと各ファイルはリンクを拒否するが、`COACH_TRACE_DIR` の親経路は検査しない | 信頼できる場所（ホーム下）に置く運用。必要なら `realpath` 比較を追加 |
| P15-3 | 履歴 API は JSONL 全体を同期的に読む | 11 MB のゲームで位置参照 p95 107 ms、一覧 p95 58 ms。並行取得時も状態取得 p95 88 ms で目標内だが、ゲーム・プレイヤーが増えると悪化 | Phase 2 でオフセット索引またはキャッシュ |
| P15-4 | 容量・保持期間の管理なし | 2 人・540 手で約 13 MB | 削除・圧縮方針を Phase 3 までに決める |
| P15-5 | `uncertain` の判定は「同じプレイヤーの最後の確定状態と同カウンタ・別内容、かつ他者のイベントなし」のみ | 記録されない他者の手（AI・トレース無効時）でカウンタが動かない変化があれば `uncertain` になり得る（誤って `rollback-detected` にはならない） | 実運用の発生頻度を見て調整 |
| P15-6 | 記録時の判定は毎回のカウンタ比較（計画の「初回観測時」から変更） | 再起動以外の巻き戻り（キャッシュからの退避・再読込）も検出できる。コストは比較のみ | — |
| P15-7 | 1 ファイルに複数行を書くトランザクションはない | 計画どおり。孤立スナップショットは許容、参照先不在イベントは 0 を保証 | — |
| P15-8 | `health` は API 呼出し時点のプロセス内カウンタ | 再起動でリセットされる | 永続的な監視が必要なら Phase 2 以降でメトリクス化 |
