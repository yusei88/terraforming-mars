## 2. Gate B のグラフで作らない関係

- FEEDS_RESOURCE（他カードへの資源追加は対象選択で、検証済みアダプタがない）、AMPLIFIES（他カードのプレイで発動する効果はカード固有コード。例: Media Group）。
- 海洋要件の UNLOCKS（海洋はタイル配置で未解析）、全員のタグを数える要件、トラックのボーナス（酸素 8 % で温度、温度 0 ℃ で海洋など）、M€ を与えるカード（全カードに効くため結ばない）。
- カタログ全体の参考例（catalog-only ノード）。
- 欠けているエッジは「関係なし」を意味しない。

## 3. 効果の未解析（基本・企業時代、[phase2-coverage.md](phase2-coverage.md)）

- 基本 148 枚: supported 62 / partial 64 / unsupported 22。企業時代 73 枚: 36 / 16 / 20 / none 1（Gate B でタグあたり VP を原子化し 2 枚の分類が変化）。
- 未解析の主因: カード固有コード（80 件）、タイル配置（34）、対象選択（20）、式による量（19）、選択（7）。
- タイル配置は、配置で上がる酸素・海洋・TR・配置ボーナスを含めて未解析。カードの価値に大きく効くため、Gate D の前に「配置の必要性」だけでなく何を数値化するかを決める必要がある。
- `global` 原子はパラメータの段数のみ。TR の増加と温度・酸素のボーナス（-24 ℃・-20 ℃ の熱生産、酸素 8 % での温度上昇など）、上限到達時の扱いは Gate D で規則として実装し、エンジン Golden で検証する。Golden では閾値をまたがない局面で TR = 段数を確認済み。
- 要件を評価できないカード: 基本 10、企業時代 5（隣接条件、カード固有のプレイ条件など）。

## 4. 制約

- 割引予測は「エンジンが今計算したコスト」を起点にするため、コストが分かるのは手札・ドラフト・購入候補・プレイ候補のカードだけ。カタログのみのカード（未所持）は印刷コストからの計算になり、Playwrights・Turmoil などの補正は含まれない（基本セットでは影響なし）。
- 要件緩和は、パラメータ指定のある緩和（拡張）を未解析として `conditional` にする。
- 要件の `conditional` は規則が変わり得ることを示すだけで、満たすか否かの計算値は `gap` に残る。
