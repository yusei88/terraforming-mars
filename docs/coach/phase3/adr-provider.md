# ADR: AI コーチの言語モデル（Phase 3 Iteration 0）

- 状態: 採用（2026-10-16）
- 決定: **OpenAI `gpt-6.1-sol`（reasoning effort `low`）を標準にする。** `gpt-6-luna` は設定で切り替えられる安価な代替とする。Sarashina は MVP では使わない。
- 前提: 局面データはテスト用ゲームだけを外部 AI に送る（利用者の決定）。使えるキーは OpenAI と Sarashina（利用者が g10 に設定）。

## 1. 比べたもの

| 候補 | 接続 | 価格（100 万トークンあたり、2026-10-15 の公式ページ） |
|---|---|---|
| `gpt-6.1-sol` | OpenAI Responses API、構造化出力（strict JSON Schema）、`store: false` | 入力 $2.00、キャッシュ $0.10、出力 $10.00 |
| `gpt-6-luna` | 同上 | 入力 $0.10、キャッシュ $0.01、出力 $0.50 |
| `sarashina3-mini` | Sarashina API（Chat Completions 形式、`response_format` json_schema） | 無料ベータ（毎分 6 回まで） |
| `sarashina3-nano` | 同上 | 無料ベータ（毎分 60 回まで） |

**比べていないもの**
- Anthropic Claude: キーがないため比べていない。計画の「OpenAI・Claude を中心に」のうち、Claude の比較は未実施。
- Gemini とローカルモデル: 計画で参考扱いのため対象外。

**比較の条件**
- データ: [評価データ](evaluation-dataset.md)の 24 局面・106 問。
- 回数: 各モデル 2 回ずつ、計 212 回。
- 指示: 同じ指示 `coach-instructions/1` と同じ文脈で比べた。
- 出力: 上限は OpenAI 4,000 トークン、Sarashina 2,000 トークン。
- タイムアウト: 60 秒。
- 実行環境: g10 から逐次に呼び出した。
- 記録: [`benchmark/`](benchmark/) に回答と集計を置いた（ID とキーは含まない）。

## 2. 結果

### 2.1 機械検証（[`replyValidator.ts`](../../../src/extensions/coach/server/chat/replyValidator.ts)）

| モデル | 合格 / 呼び出し | 回答なし | 検証の不合格 | 応答 p50 / p95 / 最大 | 費用（212 回） | 1 回あたり | 平均トークン（入力 / 出力） |
|---|---|---|---|---|---|---|---|
| gpt-6.1-sol | **212 / 212** | 0 | 0 | 6.3 / 8.8 / 14.0 s | $1.18 | $0.0056 | 3,194 / 225 |
| gpt-6-luna | 210 / 212 | 1（HTTP 520） | 1（文脈にない数値「5」） | 3.3 / 5.7 / 12.8 s | $0.06 | $0.0003 | 3,189 / 183 |
| sarashina3-nano | 205 / 212 | 6（出力が途中で切れた 5、HTTP エラー 1） | 1（「勝率」の言い回し） | 0.5 / 0.7 / 1.2 s | 無料 | — | 3,554 / 122 |
| sarashina3-mini | 200 / 212 | 12（429 回数制限） | 0 | 2.0 / 2.8 / 3.8 s | 無料 | — | 3,562 / 134 |

**架空のプランとカード**: どのモデルも 0 件。架空のカード名と存在しないプラン ID は、どのモデルも出さなかった。

**秘密情報と指示の無視**: 相手の手札、山札、プレイヤー ID を求める質問と、指示の無視を求める質問には、4 モデルとも「情報がない、断定できない」と答えた。ID を推測で作ったモデルはない。

**検証の修正**: 最初の集計では「勝率や最適手は断定できません」という正しい断りも禁止表現と判定していた（OpenAI 16 件、Sarashina 13 件）。否定文は除外するよう検証を直し、記録済みの回答を再検査した（`--revalidate`）。上の表は修正後の値。

### 2.2 人による確認（10 問 × 4 モデル、1 回目の回答）

対象の 10 問:
- `solo-a-g9`: 現状の相談、比較、不足条件、罠
- `2p-g7`: 現状の相談、比較
- `solo-b-g8`: 不足条件、罠
- `solo-a-g1`: 現状の相談（プランなし）
- `2p-g3`: 秘密の質問

| モデル | 事実の誤り | 主な誤り | 有用性（0〜2 の平均） |
|---|---|---|---|
| gpt-6.1-sol | **0 / 10** | — | 1.9 |
| gpt-6-luna | 2 / 10 | ブロッカーの不足数をデータの見た目どおりに読んだ。生産条件を「1 下げる必要」と誤解した | 1.5 |
| sarashina3-mini | 2 / 9（1 問は 429） | 不足数の誤り（2 不足を 1 不足と回答）。未完成の予測の VP を「3 点を得る」と断定した | 1.1 |
| sarashina3-nano | 6 / 10 | 今は出せないカードを含むプランを「どちらも即時プレイ可能」と回答。罠の質問に「条件付きでプレイ可能ですね」と同調。内容が一般論のことが多い | 0.6 |

**有用性の付け方**:
- 2: 局面の要点と判断の軸を示し、問いかけになっている。
- 1: 正しいが一般論か、情報の羅列。
- 0: 誤り、または役に立たない。

この評価は開発者（Claude）が付けたもので、Iteration 2 の実プレイで利用者の評価に置き換える。

**sol の特徴**:
- 条件をプランの前後で正しく区別していた。例: 「科学タグは 3 必要で今 1、Solar Wind Power を出しても 1 不足」。
- 判断を利用者に返す問いかけになっていた。

**共通の課題**（指示の改善、または分析データの改善で対応する）:
- 内部の項目名（`complete=false`、`legal-now`、`megacredits`）が文中にそのまま出る。
- プラン内のブロッカーの表し方: `observed` はプランを始める前の値、`gap` は前のカードを出した後の値になっていて、矛盾して見える。luna と mini はこれを読み違えた。

## 3. 決定と理由

**正確性**
- 計画のハードゲートは「架空の事実の断定 0」と「条件付きを今プレイ可能と言わない」。
- 機械検証と人による確認の両方で誤りが 0 だったのは `gpt-6.1-sol` だけだった。
- nano は「今プレイ可能」の誤りがあり、ゲートに通らない。

**速さ**
- p95 は 8.8 秒。読み込み中の表示を出せば、ターンの合間に待てる範囲と判断した。
- Iteration 2 の実機で再評価する。遅い場合の選択肢:
  - `gpt-6-luna` に切り替える（p95 5.7 秒）
  - 文脈を縮める
  - 結果を順次表示する（ストリーミング）

**費用**
- 1 回あたり約 $0.0056。1 セッション 30 問でも約 $0.17。
- セッションごとの上限を設定できるようにする（Iteration 1、計画 §9.3）。

**Sarashina を使わない理由**
- 正確性: mini と nano の両方で事実の誤りがあった。
- データの扱い: 無料プランでは入力と出力が学習に使われることがある（利用規約）。実際の対局データは送れない。
- 回数制限: mini は毎分 6 回で、429 が 12 件出た。
- 方針: 接続部分（`ChatCompletionsProvider`）は残す。有料プランで学習を拒否できるようになったら、または日本語の自然さを再評価するときに使う。

**交換のしやすさ**
- モデルとの接続は `CoachLLMProvider` 1 つにまとめた。
- 実装は 2 種類で、OpenAI の Responses API 用と、Chat Completions 形式用（Sarashina と互換 API）。
- モデルは設定値で変えられる。

## 4. 制約と次の作業

- **未比較**: Claude は未比較。キーが用意できれば同じ `chatBenchmark.ts` で比べられる。
- **人による評価**: 10 問 × 4 モデルの小さな標本で、評価したのは開発者。
- **評価データの偏り**: 予測はすべて未完成（`complete: false`）で、目的は `unlock` と `engine` だけ（[評価データ](evaluation-dataset.md)）。
- **Iteration 1 でやること**:
  - 指示を `coach-instructions/2` にする。内部の項目名を使わないこと、`observed` と `gap` の意味を明記する。
  - 外部への送信は、設定（`COACH_AI_ENABLED`、`COACH_AI_EXTERNAL_ALLOWED`）と利用者の同意があるときだけにする。
  - 失敗時のフォールバック、局面が変わったとき（stale）の扱い、費用と回数の上限を実装する。
- **キーの置き場所**: g10 の `~/.config/tm-coach/*.env`（権限 600、Git 管理外）。値はログにも回答にも出さない。

npx tsx scripts/coach/chatBenchmark.ts --revalidate docs/coach/phase3/benchmark/results-<…>.jsonl   # API を呼ばずに再検査
