# Claude Code 着手プロンプト — Terraforming Mars「選択主導型AI戦略コーチ」

次の仕様を `yusei88/terraforming-mars` に実装してください。本指示と併せて `terraforming_mars_phase3_choice_driven_plan.md` をリポジトリの `docs/coach/phase3/choice-driven-design.md` 等に取り込み、コードとの整合性を確認してください。

## 目的（最優先）

「現在選べる具体的な行動・将来の戦略プランを並べる → 私が選択する → AIが選択の強み、弱点、数手先の影響と問いを返す」体験を作ります。

- AIは**先に最善手を押し付けない**。選択するのはプレイヤー。
- AIは**迎合しない**。不利な選択ならその理由を根拠付きで示す。
- ゲームルールはゲーム本体・Phase 2分析を正とする。LLMによる独自の数値計算や合法性の捏造は禁止。
- **選択≠ゲームへの入力**。AIコーチは完全な読み取り専用。
- 自由チャットは優先度低。初期MVPはボタンと選択肢だけで一連の体験を完結させる。

## 今回の着手範囲

### Step 0: ADRと実装契約を整える

- 既存の`gpt-6.1-sol`選定は**暫定採用**。Iteration 0の比較数値は残し、選択後のコーチング能力では未評価と記載する。
- `docs/coach/phase3/choice-driven-design.md`に最新版の目的・状態遷移・Now/Futureの区分・データ契約・セキュリティを記録する。
- 既存の自由質問モードは破壊せず補助機能として残す。初期UIから前面に出さない。

### Step 1: 選択肢をプレイヤーに表示する（まずこれを実際に動かす）

- `ChoicePresenter`相当の**サーバー側で検証可能な選択肢一覧**を作成する。本人の合法入力から始め、現時点のNowと将来のFutureを区別する。ゲームの入力に対応しない候補をNowに入れない。
- `CoachAnalysisV1.candidates`はFutureとして再利用。先頭カードが`legal-now`であってもプラン全体が今すぐ実行可能とは限らないことを明示する。
- 最初の縦切りは`projectCard`、`or`、既存の候補プランを中心に実装して構わない。他の種類は根拠のある未対応表示から始める。
- Gate Fの既存CoachPanelへ選択UIを追加する。プレイヤーが選択した時点ではゲームを変更しない。
- Now/Futureが0件のとき、他の人のターンや解決中などのときも正しく表示する。

### Step 2: 選択に応じたコーチングを縦切りで接続

- 例: `GET /api/coach/options?id=...`, `POST /api/coach/counsel?id=...`。既存ルート/POST規約に合わせて実装し、**本人認可、CSRF、no-store、入力長制限、レート制限、局面再照合**を入れる。
- リクエストには選択対象ID、位置トークン、言語、必要なら比較先IDを含める。クライアントからカードの合法性/費用を送らせず、サーバー側で再確認する。
- モデル用のコンテキストは**選んだ行動に関連する根拠、代替プラン、未対応の影響**を含め、相手の秘密・山札順・プレイヤー/ゲームIDを含めない。
- まずテンプレートで「選んだ行動の強み・注意点・先読み可能な範囲・問い1つ」が返る状態を作り、その後既存の`CoachLLMProvider`で1モデル接続する。
- 外部AI接続は**初期状態オフ、サーバー設定と利用者の同意が揃ったときのみオン**。
- 数値がコンテキストのどこかにあるだけでは正しさを保証できない。事実と根拠IDをひもづけ、誤帰属を可能な限り検出。検証失敗はテンプレートにフォールバック。
- 生成中にゲームが進めば`stale`を示し、旧回答を今の答えとして上書きしない。

### Step 3: 実機で通すための最小UX

- タブレットの縦・横でゲームボタン/操作シート/Undoを隠さない。既存のGate F配置を踏襲し、必要なら内部スクロール等を使う。
- 基本のボタンは「この選択を検討」「他案と比較」「根拠を見る」「選び直す」「閉じる」。自由形式入力は不要または折りたたむ。
- コーチを閉じたり失敗してもゲームが進む。LLMが落ちてもNow/Futureと根拠カードを表示する。
- 追加した静的UI文言は `CLAUDE.md` に従い**全16言語で同一PRに翻訳**し、`npm run lint:i18n`等で確認。

## 絶対に避けること

- 早々に全ゲーム・全拡張・全ターンの探索を作り始めない。
- AIにゲームのプレイAPI/ゲームを変更するツールを渡さない。
- 選択の前に最善手を自動発表しない。ユーザーが選んだ後も無条件に賛同しない。
- 研究フェーズ購入、プレイ、複数選択、条件付きプランを同じ「今すぐ合法な一手」と断定しない。
- 本体の完全情報に含まれる未知山札/対戦相手秘密を、戦略先読みの確定情報に使わない。
- `Game.serialize()`での`deferredActions: []`を無視し、任意の進行途中局面を正しく複製できると仮定しない。
- 「最善」「必勝」「勝率」の断定、出所を確認できない数値の表示。
- 新UIを英語だけで導入しない。秘密をGit/ログ/外部LLMに流出させない。

## 試験と完了条件

- サーバー単体: 選択肢の正確性、Now/Future、本人以外の認可、選択ID/局面トークンの不正、AIオフ、失敗フォールバック、未対応タイプ。
- セキュリティ: 個人の秘密ID/山札順/他人の秘密、プロンプト注入、ゲーム非変更、CSRF/制限。
- UI: 縦/横、選択→分析→閉じる、入力中・キャンセル・選び直し、ゲーム操作非阻害。
- 代表局面: ソロ、対人、研究購入、アクション、待機、Undo、ゲーム終了、分析候補0。
- `npm run lint`, `npm run lint:i18n`, Coachテスト、必要なサーバー/クライアント回帰、ビルドを実行。既存の既知失敗はベースラインと区別。
- 完了デモ: **自分のゲームから実際の合法な選択を1つ選び、その根拠付きコーチングを見てからゲームプレイを正常に続けられる**。
