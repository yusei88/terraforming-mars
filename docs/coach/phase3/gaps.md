# Phase 3 未対応・制約

最終更新: P3-CD-1（2026-10-16）。

## 1. 選択肢（[choice-driven-design.md](choice-driven-design.md) §4）

P3-CD-1 で検討の対象にするのは、プロジェクトカードのプレイ、実行可能な標準プロジェクト、決まった行動（`option`）、将来のプラン。

次の入力は一覧に出すが、検討の対象外とする（P3-CD-2 で入力の種類ごとに確かめて広げる）。
- 青カードのアクション
- 研究フェーズの購入
- Sell patents、企業選択などの複数選択
- 開始時の複合入力
- タイル配置、支払いなど、行動の途中で答える入力

## 2. 先読み

- 根拠にできるのは、Phase 2 の 1〜3 枚のプランと 0〜3 回の生産フェーズの予測だけ。行動回数単位の先読み（分岐探索）は P3-CD-3 で、検証ゲートを通したものだけを入れる。
- `Game.serialize()` は `deferredActions` を空で書き出す。途中の局面を正確に複製できるとは仮定しない。

## 3. 分析データ

- プラン内のブロッカーは、`observed` がプランを始める前の値、`gap` が前のカードを出した後の値になっている（Iteration 0 で発見）。P3-CD-2 で意味の明確な事実に変換する。

## 4. モデル

- `gpt-6.1-sol` は暫定。選択へのコーチングのベンチマーク（計画 §7）と実プレイの評価で再判断する。
- Claude は未比較（キーなし）。
- Sarashina は無料プランでは入力が学習に使われることがあるため、実対局のデータは送らない。

## 5. P3-CD-1 の実装の制約

- **取り消し**: パネルを閉じると、クライアントは要求を取り消す。サーバー側のモデル呼び出しは、タイムアウトまで続くことがある（結果は捨てる）。ゲームの要求オブジェクトに切断のイベントがないため。
- **呼び出しの上限**: モデル呼び出しの上限と毎分の上限はプロセス内で数える（再起動で戻る）。
- **カード名**: モデルの文中のカード名は英語のまま（検証のため）。表示側での翻訳は今後。
- **比較**: カード同士の比較の問いは、テンプレートでは費用と関係を並べるだけ。優劣の判定はしない。
- **確定事実**: 標準プロジェクトとゲームの行動（パスなど）は、費用と残金だけで、数値の分析はない。
