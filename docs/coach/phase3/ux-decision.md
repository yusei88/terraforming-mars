# UX の決定（Phase 3 Iteration 0）

状態: 採用（Iteration 1 の PR #P3-1 で実装し、PR #P3-3 で縦・横を実機確認する）。2026-10-15。

## 1. 比べた案

| 案 | 内容 | 評価 |
|---|---|---|
| A | 画面端の起動ボタン → パネル（おすすめ質問のボタン＋入力欄） | **採用** |
| B | 常設の小さな戦略サマリー＋詳細シート | 不採用 |

B を採らない理由（Gate F の実機確認から）:
- タブレット表示のゲーム画面は、上部バー（52px）、盤面、下部ナビ（68px）、アクションシート（下から最大 82 %）で埋まっている。常設の領域を置くと、盤面かアクションシートのどちらかを常に削ることになる。
- 常設の要約は局面ごとに変わる。ユーザーが頼んでいない情報を出し続けることになり、計画の「自動ポップアップや頻繁な割り込みをしない」に反する。

## 2. 採用した配置（計画 §5.1 からの変更）

計画は「縦はボトムシート、横はサイドパネル」としていた。この配置は Gate F の実機確認で、ゲームの操作を隠すことが分かっている（[Phase 2 設計 §11](../phase2-design.md)）。

- ゲーム画面は 1 つの重なり順の文脈（`mb-home`、`z-index: 0`）にある。拡張のパネルは、ゲームのシートより上か、ゲーム画面全体より下かのどちらかにしかできない。
- 下から開くパネルは、アクションシートと下部ナビを覆った。
- 横のサイドパネル（上から下まで）は、「世代終了」と「Undo」を覆った。

そのため Gate F と同じ配置にする。

| 向き | 配置 | 最大の高さ |
|---|---|---|
| 縦 | 上部バーの直下、全幅 | 40vh |
| 横（900px 以上） | 右上、幅 `min(440px, 45vw)` | 45vh |

チャットでは回答と入力欄が加わり、高さが足りなくなる。最大の高さは Iteration 1 の実機確認で調整する。超える分はパネルの中でスクロールさせる。

## 3. 起動

**現状の問題**: Gate F の入口はゲームメニュー（☰）だけ。タブレット表示ではメニューが「Players」画面にしかなく、開くまでに 3 回の操作が要る。

**決定**: 閉じている間、プレイヤーのページにだけ小さな起動ボタン（電球アイコン、44px 以上）を出す。
- 位置: 右端、上部バーの直下。盤面の右上は余白で、アクションシートや下部ナビとは重ならない。
- メニューの入口も残す。
- 観戦者のページには出さない。

## 4. パネルの中身

| 段 | 内容 |
|---|---|
| 上 | 局面の状態。分析中／最新／局面が変わった（stale）／AI 無効 |
| 中 | プランの概要。最大 3 件、目的が違うものを優先。Gate F の表示を折りたたみ式にする |
| 下 | おすすめ質問のボタン（今どうする？／P1 と P2 の比較／不足条件）、自由入力欄、送信 |

- **回答の表示**:
  - AI の文章とは別に、回答が参照したプランをサーバーのデータから「事実カード」として描く（費用、可否、ブロッカー）。
  - AI の文章に書かれた数値は、検証で文脈にあることを確かめたものに限る。
- **AI が使えないとき**（外部送信の未許可、キー未設定、失敗）: 入力欄の代わりに、理由とプラン（Gate F と同じ表示）を出す。ゲームの操作には影響しない。
- **閉じる**: 「閉じる」で閉じる。生成中なら取り消す（Abort）。

## 5. 実機で確かめること（Iteration 1）

- 縦・横で、パネルを開いたまま「アクション」の操作ができるか。
- 入力時に画面キーボードが出ても、入力欄と回答が隠れないか。
- 起動ボタンが盤面のタップと干渉しないか。
- 回答を待つあいだ（数秒）、ゲームを続けられるか。
